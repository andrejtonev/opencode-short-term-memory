# Acceptance runners

Use this map when choosing a check. A source test, a fresh package consumer and a native host run prove different things. [RC Readiness](RC-READINESS.md) records frozen release results; [Feature Matrix](FEATURE-MATRIX.md) describes the generation contracts. RC11 review fixes are not covered by RC10 receipts, and this guide records no new native or live-provider qualification.

Run commands from the repository root unless stated otherwise. Build current source before a runner that consumes `dist/`. Install repository dependencies with Bun; V2 fixture runners also need `bun install` in `fixtures/v2-generation-probe/`. Supply explicit archive and host paths: changing a package version in an old runner does not establish release acceptance.

## Maintained checks

| Runner / command                                                                                         | Prerequisites and input                                                                                                                                                                 | What it proves / limits                                                                                                                                                                                              |
| -------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bun test --isolate test/CHANGED-AREA.test.ts`, `bun run typecheck`, `bun run build`                     | Repository dependencies; choose focused regressions for the change.                                                                                                                     | Source behavior and declaration/build compatibility. Mock SDK tests do not qualify a native host or model.                                                                                                           |
| `bun scripts/package-acceptance.ts /absolute/path/product.tgz`                                           | Built tarball and Bun/npm package installation access.                                                                                                                                  | Fresh production consumer, public imports and strict declaration consumers from the exact archive. Does not activate OpenCode.                                                                                       |
| `node scripts/v1-native-menu-acceptance.cjs NATIVE_EXE PRODUCT_TGZ`                                      | Windows, explicit V1 host executable, repository `node-pty`, exact tarball.                                                                                                             | Native menu, paged output, confirmation and path-only Logs with deterministic provider. Archive extraction uses repository dependency junctions; fresh consumer installation is a separate gate.                     |
| `node scripts/v2-native-reader-acceptance.cjs HOST_DIRECTORY PRODUCT_TGZ`                                | Windows, explicit V2 host directory, repository `node-pty`, exact tarball.                                                                                                              | Native scrollable reader/navigation and path-only Logs without model generation. Uses repository dependency junctions. Does not qualify V2 generation.                                                               |
| `node scripts/v1-clean-tools-acceptance.mjs NATIVE_EXE INSTALLED_PACKAGE_ROOT`                           | Explicit V1 executable and installed package root.                                                                                                                                      | Deterministic native clean-session tool execution guard, primary-session controls and injection isolation. Optional `--live` requires deliberate provider authorization; it is not a default check.                  |
| `bun fixtures/v2-generation-probe/host-probe.ts`                                                         | Fixture dependencies, pinned OpenCode `2.0.12`, deterministic provider.                                                                                                                 | Exploratory SDK/host lifecycle contracts. Uses the fixture implementation, not packaged STM release qualification.                                                                                                   |
| `bun fixtures/v2-generation-probe/production-update-probe.ts`                                            | Current `dist/`, fixture dependencies and pinned host. Set `PROBE_SCENARIO` to `ordinary`, `manual-update`, `reset` or `setup`.                                                         | Current production update/action behavior with deterministic responses. Manual-update/setup wrappers suppress automatic context callbacks and record that suppression; they do not prove full automatic integration. |
| `bun fixtures/v2-generation-probe/tui-output/production-acceptance.ts`                                   | Linux, `tmux`, fixture dependencies, current build.                                                                                                                                     | Current production UI/action contracts with a deterministic provider. Stages current files with repository dependencies; not an exact frozen archive consumer.                                                       |
| `bun fixtures/v2-generation-probe/tui-output/native-multichunk-acceptance.ts /absolute/path/product.tgz` | Linux, `tmux`, fixture dependencies and exact archive. Temporary parent defaults to the OS temp directory; optional `STM_NATIVE_SANDBOX_PARENT` must be an existing absolute directory. | Fresh production package plus native deterministic multichunk behavior. Wrapper forwards the default export without replacing update callbacks. Does not establish real-model summary quality.                       |

Probe deadlines settle callers even when SDK work ignores cancellation. Late successful service startup retains cleanup ownership, and the command wrapper forwards signals only to its direct owned child. Failed startup before an endpoint is returned, force-termination on Windows, and grandchildren still need native cleanup qualification. A timeout or incomplete cleanup is a failed run, not a passing receipt.

## Historical and specialized investigations

| Runner / record                                                                                                                                                                                               | Scope                                                                                                                                                                                                                                                                 |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `scripts/published-v1-e2e.ts`                                                                                                                                                                                 | Historical legacy server-command recipe: accepts RC1-RC8 only and rejects newer versions before registry/native installation (a supplied tarball manifest is still extracted for version inspection). Use the native V1 menu runner for the current command contract. |
| `scripts/published-v2-e2e.ts`, `scripts/rc-keyboard-chat.ts`, `scripts/rc-setup-acceptance.ts`                                                                                                                | Version/scenario-specific investigations, not the maintained release gate. Inspect host/API/provider assumptions before reuse.                                                                                                                                        |
| `fixtures/v1-v2-dual-proof/`                                                                                                                                                                                  | Earlier SDK shape/marker experiments with their own pins. Useful historical API evidence, not current STM acceptance.                                                                                                                                                 |
| `scripts/windows-config-sweep.ts`, `scripts/windows-azure-acceptance.ts`                                                                                                                                      | Specialized native/provider investigations. Recent harness regressions have local tests; a passing unit test does not qualify the native sweep. Real Azure/provider runs require explicit authorization.                                                              |
| [Windows Azure guide](WINDOWS-AZURE-ACCEPTANCE.md), [dated results](WINDOWS-AZURE-RESULTS-2026-10-20.md), [RC acceptance inventory](RC-ACCEPTANCE-MATRIX.md), [V1 manual acceptance](V1-MANUAL-ACCEPTANCE.md) | Archived version/hash/host-specific records. Keep their results unchanged and follow current runner contracts instead of copying old command expectations.                                                                                                            |

Receipts beneath ignored `.opencode/rc*/` directories are local provenance and are absent from a clean clone. Keep exact archive hashes, source/tag identities, host versions, provider mode and unrun scopes together when reporting any new check. Do not promote deterministic provider evidence to semantic quality or tool-isolation proof beyond the assertions actually exercised.
